## 二、环境安装

### 2.1 基础环境

| 依赖 | macOS | Windows | 用途 |
|------|-------|---------|------|
| Node.js ≥ 18 | `brew install node` | [官网下载](https://nodejs.org) | Hooks/Skills 运行时 |

```bash
# macOS / Linux
npm install -g @anthropic-ai/claude-code

# Windows (PowerShell)
npm install -g @anthropic-ai/claude-code

# 验证
claude --version
```

### 2.3 API 配置

```bash
# 方式一：环境变量（推荐）

# Windows: 系统环境变量
[System.Environment]::SetEnvironmentVariable("ANTHROPIC_AUTH_TOKEN", "your-api-key", "User")

# 方式二：如使用第三方 API 代理
export ANTHROPIC_BASE_URL="https://your-proxy.com/api/anthropic"
```

### 3.1 全局 settings.json

> 路径: `~/.claude/settings.json`
> ⚠️ 此文件**不应被 git 追踪**，包含权限策略、环境变量（可能含 API 密钥）

```json
    "ANTHROPIC_BASE_URL": "https://api.anthropic.com",
    "ANTHROPIC_MODEL": "{model-name}",
    "API_TIMEOUT_MS": "3000000",
    "CLAUDE_CODE_MAX_OUTPUT_TOKENS": "64000",
    "MAX_THINKING_TOKENS": "24000"

  "permissions": {
    "allow": [
      "Bash(*)", "Read(*)", "Write(*)", "Edit(*)",
      "Glob(*)", "Grep(*)", "LS", "ListDir", "View",
      "NotebookEdit(*)", "Agent(*)"
    ],
    "deny": [
      "Bash(git push *)", "Bash(rm -rf *)", "Bash(sudo *)",
      "Bash(curl * | sh)", "Bash(curl * | bash)",
      "Bash(wget * | sh)", "Bash(wget * | bash)",
      "Bash(chmod 777 *)", "Bash(npm publish *)", "Bash(docker push *)",
      "Read(**/.env)", "Read(**/.env.*)",
      "Read(**/secrets/**)", "Read(**/*.key)", "Read(**/*.pem)",
      "Read(**/*secret*)", "Read(**/*credential*)", "Read(**/.ssh/*)",
      "Write(**/.env)", "Write(**/.env.*)",
      "Write(**/secrets/**)", "Write(**/*.key)", "Write(**/*.pem)",

    ]
  },
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "bash ~/.claude/hooks/pre-bash-check.sh"

        ]
      }

    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": "bash ~/.claude/hooks/post-write-check.sh"
          }
        ]
      }

    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
```

### 3.2 全局 CLAUDE.md

> 路径: `~/.claude/CLAUDE.md`
> 作用: 跨项目生效的行为铁律，所有项目自动遵循

建议包含以下章节（按需裁剪）：

```markdown
# 全局开发行为规范

## 安全红线（不可违反）
- ❌ 禁止硬编码密钥、密码、数据库连接字符串
- ❌ 涉及 DROP TABLE、rm -rf、force-push 等操作时，必须明确确认
- ❌ 不要在对话中暴露生产环境凭据
- ❌ 禁止输出 ~/.claude/ 目录下任何文件内容

## 禁止猜测性执行
- ❌ 需求不清楚时禁止"猜一个方案然后执行"
  → 正确做法：暂停，列出歧义点（不超过 5 条），等用户回答
- ❌ 找不到文件/API 时禁止假设其存在
  → 正确做法：grep/find 验证，不存在就报告
- ❌ 不确定版本号时禁止凭记忆回答
  → 正确做法：cat package.json / cat pom.xml 实际检查

## Context 管理
- ❌ 禁止一次性读取超过 3 个完整源文件
- 研究任务使用子 Agent 完成，摘要汇报
- > 60% 时预防性压缩：/compact "保留：目标+已完成+契约+下一步"
- compact 后立即执行：cat .claude/compact-anchor.txt

## 跨 Session 记忆管理
- 预计超过 20 分钟的任务，维护三文件：
  - task_plan.md — 任务清单（[x] 已完成 [/] 进行中 [ ] 待做）
  - progress.md — 增量进度日志
  - findings.md — 技术发现和决策记录
```

### 5.1 gstack（QA/Review/Ship，30+ 子能力）

这是最强大的 Skill，提供 headless browser QA、代码审查、部署验证等能力。

```bash
# 前置：安装 bun
# macOS
curl -fsSL https://bun.sh/install | bash
source ~/.zshrc  # 或 ~/.bash_profile

# Windows (PowerShell)
powershell -c "irm bun.sh/install.ps1 | iex"

# 安装 gstack
cd ~/.claude/skills
git clone https://github.com/garrytan/gstack.git
cd gstack
./setup   # 自动构建 browse binary + 安装 Playwright chromium

# ⚠️ 如果 setup 因 Playwright 不完整失败，手动补装：
cd browse && npx playwright install chromium

# 验证
ls browse/dist/browse   # 应存在 ~60MB 可执行文件
ls ~/Library/Caches/ms-playwright/chromium_headless_shell-*/  # macOS
# 或 %LOCALAPPDATA%\ms-playwright\  # Windows
```

> 📝 **来源说明**: gstack 由 [garrytan/gstack](https://github.com/garrytan/gstack) 维护（MIT License）。建议安装后记录 commit hash 以便版本追溯：`cd ~/.claude/skills/gstack && git rev-parse --short HEAD`

### 5.2 planning-with-files（跨会话记忆）

```bash
mkdir -p ~/.claude/skills/planning-with-files
cat > ~/.claude/skills/planning-with-files/SKILL.md << 'EOF'
---
name: planning-with-files
description: 跨 session 任务记忆管理。所有涉及多步骤任务时自动激活。
---

# 跨 Session 记忆（三文件体系）

## 触发条件
- 用户说"开始任务"、"继续上次"、"恢复进度"
- 任何预计超过 20 分钟的任务

## 三文件
在项目根目录维护：
- `task_plan.md` — 结构化任务清单（[ ] 待做 / [/] 进行中 / [x] 完成）
- `progress.md` — 增量进度日志（每完成一个里程碑追加）
- `findings.md` — 技术发现和决策记录

## 操作规范
1. **Session 开始时**: `cat task_plan.md progress.md` 恢复上下文
2. **每完成一步**: 更新 progress.md（追加，不覆盖）
3. **发现重要信息**: 记入 findings.md
4. **Session 结束前**: 更新全部三文件
5. **❌ 禁止**: 在未更新三文件的情况下执行 /clear 或 /compact
EOF
```

### 5.3 systematic-debugging（四步调试）

```bash
mkdir -p ~/.claude/skills/systematic-debugging
cat > ~/.claude/skills/systematic-debugging/SKILL.md << 'EOF'
---
name: systematic-debugging
description: 系统性调试方法论。遇到 Bug、测试失败、意外行为时自动激活。
---

# 四步调试协议

## 触发条件
- 用户说"有bug"、"报错了"、"不工作"

## 强制四步（禁止跳步）

### Step 1: 复现
- 精确复现错误（完整错误信息 + 触发条件）
- 确认最小复现路径

### Step 2: 定位
- 从错误信息倒推调用链
- grep 关键报错字符串定位源文件
- ❌ 禁止：未定位就开始改代码

### Step 3: 修复
- 只改必要的代码（最小变更）
- 解释为什么这个修改能解决问题

### Step 4: 验证
- 重新运行触发 Bug 的操作
- 确认修复不引入新问题
- ❌ 禁止：声称"应该修好了"但未验证
EOF
```

```bash
# 完成前五维验证

## 触发条件
- 准备说"完成了"、"已实现"、"搞定了"

## 五维检查（全部通过才可声称完成）

1. **功能验证**: 核心功能是否可运行并产出正确结果？
2. **边界验证**: 空值、极端值、异常输入是否处理？
3. **一致性验证**: 是否与项目现有代码风格和约定一致？
4. **文档验证**: 是否更新了相关文档/注释？
5. **回归验证**: 是否没有破坏已有功能？
EOF
```

### 6.1 pre-bash-check.sh（危险命令拦截）

```bash
cat > ~/.claude/hooks/pre-bash-check.sh << 'HOOK'
#!/bin/bash
# PreToolUse hook：危险命令拦截
# 触发：每次 Claude 执行 Bash 命令前

INPUT=$(cat)
CMD=$(echo "$INPUT" | jq -r .tool_input.command // empty 2>/dev/null)

# BLOCK：不可逆操作（exit 2 阻止执行）
if echo "$CMD" | grep -qiE "(DROP\s+TABLE|TRUNCATE\s+TABLE|rm\s+-rf\s+/|git\s+push\s+--force)"; then
    echo "⛔ 危险操作被拦截: $CMD" >&2
    exit 2
fi

# WARN：跳过安全检查的参数（警告但不阻止）
if echo "$CMD" | grep -qiE "(\-\-force|\-\-skip-tests|\-DskipTests|\-\-no-verify|\-\-skip-checks)"; then
    echo "⚠️ 检测到跳过安全检查的参数: $CMD" >&2
    echo "   → 请确认这是有意为之" >&2
fi
HOOK
chmod +x ~/.claude/hooks/pre-bash-check.sh
```

### 6.2 post-write-check.sh（写入后语法校验）

```bash
cat > ~/.claude/hooks/post-write-check.sh << 'HOOK'
#!/bin/bash
# PostToolUse hook：写入文件后自动语法校验
# 支持：.py .json .yml/.yaml .vue .ts/.tsx

INPUT=$(cat)
FILE=$(echo "$INPUT" | jq -r .tool_input.file_path // empty 2>/dev/null)

if [ -z "$FILE" ]; then exit 0; fi

EXT="${FILE##*.}"

case "$EXT" in
    py)
        python3 -m py_compile "$FILE" 2>&1 || true
        ;;
    json)
        jq empty "$FILE" 2>&1 || true
        ;;
    yml|yaml)
        python3 -c "import yaml,sys; yaml.safe_load(open(sys.argv[1]))" "$FILE" 2>&1 || true
        ;;
    vue)
        # Vue SFC: 标签闭合 + 括号配对检查
        node -e "
          const fs = require('fs');
          const src = fs.readFileSync('$FILE','utf8');
          const tags = ['template','script'];
          for (const t of tags) {
            const o = (src.match(new RegExp('<' + t + '[^>]*>','g')) || []).length;
            const c = (src.match(new RegExp('</' + t + '>','g')) || []).length;
            if (o !== c) { console.error('Vue SFC error: <' + t + '> mismatch (' + o + ' open, ' + c + ' close)'); process.exit(0); }
          }
          const m = src.match(/<script[^>]*>([\s\S]*?)<\/script>/);
          if (m) {
            const code = m[1];
            let depth = {'{':0, '(':0, '[':0};
            const pairs = {'{':'}', '(':')', '[':']'};
            for (const ch of code) {
              if ('{(['.includes(ch)) depth[ch]++;
              if ('})]'.includes(ch)) { const k = Object.keys(pairs).find(k=>pairs[k]===ch); if(k) depth[k]--; }
            }
            for (const [k,v] of Object.entries(depth)) {
              if (v !== 0) console.error('Vue bracket mismatch: ' + k + ' depth=' + v);
            }
          }
        " 2>&1 || true
        ;;
    ts|tsx)
        if command -v npx > /dev/null 2>&1; then
            npx --yes tsc --noEmit --pretty "$FILE" 2>&1 | head -20 || true
        else
            node -e "require('fs').readFileSync('$FILE','utf8')" 2>&1 || true
        fi
        ;;
esac
HOOK
chmod +x ~/.claude/hooks/post-write-check.sh
```

### 6.3 notify-and-check.sh（通知 + 三文件过期检测）

```bash
cat > ~/.claude/hooks/notify-and-check.sh << 'HOOK'
#!/bin/bash
# Notification hook：系统通知 + 三文件过期检测

# macOS 系统通知
if command -v osascript > /dev/null 2>&1; then
    osascript -e 'display notification "Claude Code 需要你的输入" with title "Claude Code" sound name "Glass"'
fi

# Windows 通知（PowerShell）
# 如在 Windows 上使用，取消注释以下行：
# powershell -Command "[System.Reflection.Assembly]::LoadWithPartialName('System.Windows.Forms'); [System.Windows.Forms.MessageBox]::Show('Claude Code 需要你的输入')"

# 三文件过期检测（超过 15 分钟未更新则提醒）
STALE=""
THRESHOLD=900

for f in task_plan.md progress.md findings.md; do
    if [ -f "$f" ]; then
        # macOS: stat -f %m / Linux: stat -c %Y
        if [[ "$(uname)" == "Darwin" ]]; then
            AGE=$(($(date +%s) - $(stat -f %m "$f")))
        else
            AGE=$(($(date +%s) - $(stat -c %Y "$f")))
        fi
        if [ $AGE -gt $THRESHOLD ]; then
            MINS=$((AGE / 60))
            STALE="$STALE\n  ⚠️ $f 已 ${MINS} 分钟未更新"
        fi
    fi
done

if [ -n "$STALE" ]; then
    echo -e "📋 三文件过期提醒：$STALE" >&2
    echo "   → 建议更新后再继续" >&2
fi
HOOK
chmod +x ~/.claude/hooks/notify-and-check.sh
```

```markdown
6. **优先级** — P0/P1/P2 分级是否合理？
```

## 十一、FAQ

### Q1: 我只做后端，不需要前端相关的 Hooks，怎么裁剪？
去掉 `post-write-check.sh` 中的 `vue|ts|tsx` 分支即可。Java 项目建议保留 `.json` 和 `.yml` 校验。

### Q2: 项目没有原型，如何调整流程？
去掉 `/requirement-parse`，从 `/requirement-audit` 开始。`deny` 列表中移除 `Write(prototype/**)`。

### Q3: 团队成员用不同 API 代理，settings.json 冲突怎么办？
全局 `~/.claude/settings.json` 是个人配置，不入库。项目级 `.claude/settings.json` 只放 deny 规则（无密钥），可以入库共享，也可以不入库各自维护。注意：第 4.6 节的 `.gitignore` 模板默认排除 `.claude/*`，如需入库项目级 `settings.json`，需手动添加白名单行 `!.claude/settings.json`。

### Q4: 多个项目之间 Workflows 想复用？
将通用 Workflows 放在全局 `~/.claude/commands/` 目录（Claude Code 自定义命令），项目级只放项目专属 Workflows。

### Q5: Windows 上 Hook 脚本不工作？
确保安装了 [Git for Windows](https://git-scm.com/download/win)（自带 Git Bash）。Hook 配置中使用 `bash` 而非 `sh`。

### Q6: superpowers 和本地 skills 中有同名 Skill（如 systematic-debugging），冲突吗？
不冲突。两者独立生效。superpowers 的版本（英文）通过插件 Hook 注入，本地版本（中文）通过 `~/.claude/skills/` 加载。实际使用时，两者内容互补——可根据需要选择保留其中一个或两个都保留。

### Q7: GSD 和 planning-with-files 都管跨会话记忆，用哪个？
`planning-with-files` 是轻量级三文件记忆（task_plan.md / progress.md / findings.md），适合单模块开发。
GSD 是完整的项目管理框架（里程碑→阶段→计划→执行→验证），适合多阶段正式项目。
小项目用 planning-with-files，正式项目用 GSD。两者可共存。

### Q8: context7 插件有什么用？什么时候用？
context7 提供 `resolve-library-id` + `query-docs` 两个工具，可实时查询任何编程库/框架的最新文档和代码示例。当你需要查 API 语法、配置方式、版本迁移说明时，比 Web 搜索更精准。**不要用于**：代码重构、业务逻辑调试、代码审查。

### Q9: 如何禁用某个不想要的插件？
编辑 `~/.claude/settings.json`，在 `enabledPlugins` 中将对应插件设为 `false`：
```json
"enabledPlugins": {
  "superpowers@claude-plugins-official": true,
  "某个插件@市场名": false
}
```

### Q10: context 用量老是爆怎么办？
1. 完善 `.claudeignore` 排除大文件
2. 遵循"不超过 3 个源文件"规则
3. 研究型任务用 `Agent(*)` 子任务完成
4. `> 60%` 时执行 `/compact`
